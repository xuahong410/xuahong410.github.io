二、微前端（逻辑上独立，运行时集成在一个系统里）

合伙人、专家库一定是「单独开发、独立运行、独立部署」的，绝对不是在“主系统里面加业务模块”。

方案二：微前端 = 合伙人、专家库都“单独开发、单独部署”​

主系统只负责：菜单、登录、框架、挂载子应用

✅ 不是在主系统里写合伙人 / 专家库的页面

✅ 而是主系统和子系统是不同的仓库 / 不同的应用

 

主应用：菜单、登录、权限

子应用：partner-app（合伙人）

子应用可独立运行、独立部署

 

技术选型

qiankun（最成熟，适合 Vue / React）

Webpack Module Federation（偏新，性能更好）

Vite + qiankun（现在也基本可用）

Wujie

七、什么时候“不该”用微前端？

❌ 只有 2～3 个人开发

❌ 合伙人 / 专家库页面不多

❌ 没有独立发布需求

👉 这种情况用「业务模块拆分」就够了

八、什么时候“一定”要用微前端？

✅ 合伙人是一个独立团队维护

✅ 专家库以后可能给外部机构用

✅ 不同模块技术栈可能不同（Vue / React）

✅ 一个模块挂了不能影响整个后台

 

三、独立子系统（完全独立的前端 + 后端 + 域名。）
